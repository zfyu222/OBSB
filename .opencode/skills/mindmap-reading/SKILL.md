# 读取和理解思维导图

适用于 OpenCode 读取以 Markdown 保存的思维导图笔记。读取原始 Markdown，在理解层级及概括关联后，再从回答中省略内部标记；不要先删除所有 HTML 注释或反斜杠。仅有截图时，不猜测不可见的 ID、概括成员或折叠后代。

## 主树与节点含义

- 根据标题级别、列表及缩进建立父子关系；节点内部的续行、段落、代码块和表格仍属于该节点。代码围栏内的标题、列表及 `mm:*` 字样都是代码内容，不作为图结构解析。
- 同级节点是并列分支，排列先后本身不证明因果、执行顺序或优先级；需要节点正文提供依据。父子层级也不一定表示类继承，应结合内容判断。
- 折叠是显示状态，不是内容删除。分析一个节点时，包含文件中保存的全部后代，而不只看图上当前可见的节点。
- beta.39 起折叠仅保存在当前视图内，重新打开主树、概括及虚拟分支均默认展开；保存不再写主树的旧折叠后缀 `^id`、概括元数据的 `expanded` 或虚拟引用的 `folds`。旧笔记仍可能含这些字段，按历史显示信息理解，不据此省略内容；新文件缺少它们是正常情况。
- YAML 属性与正文分开理解。保留 Obsidian 链接、别名、块引用及附件引用的含义；附件引用不代表已读取附件内容，遵循项目不读取附件的规则。

## 多页签

- 代码围栏外独立一行的 `<!-- mm:page {"id":"pg-1","name":"页面 1"} -->` 开始一个新页面，到下一个页面标记为止都属于该页；页面顺序就是页签顺序。`name` 是给人看的页签名，`id` 只用于页面身份。
- 没有页面标记的文件是单页；单页文件保存时不会自动加标记。有标记时，标记前的正文属于第一页。
- 各页是相互独立的导图：每页都有自己的根节点、子树、`mm:relations` 和概括子树区。不要把不同页面的分支合并成一棵树，也不要跨页配对父子关系；回答时按页签名称区分，例如“第 2 页（方案对比）里……”。
- `mm:grafts` 仍是全文件唯一的一行，位于所有页面之后，`source` 和 `target` 可以属于不同页面。理解跨页嫁接时先按页面分别读出各自的正文，再按 ID 连接；来源页的正文不会在目标页重复出现。
- `mm:relations` 与概括成员只在其所在页面内有效。节点 ID 在整份文件中唯一，跨页同名文字不代表同一节点，按 ID 判断。
- 读到损坏或重复的页面标记时，说明无法拆分页面，按单页正文理解并保留原文，不猜测页面归属。

## 独立概括子树

以下标记仅在代码围栏外按插件格式解释：

| 标记 | 含义与读取方式 |
| --- | --- |
| `<!-- mm:node {"id":"n-a"} -->` | 原节点的稳定身份，建立 ID 到原节点的映射；ID 不是正文知识 |
| `<!-- mm:summaries:start {"version":1} -->` 与 `<!-- mm:summaries:end -->` | 文件末尾概括子树区的边界；区内标题和列表不挂入原主树，不能仅凭“概括子树区”标题划分 |
| `<!-- mm:summary {"id":"s-1","members":["n-a","n-b"],"expanded":true} -->` | 所在标题是概括根，后续列表是它自己的子树；`members` 引用原节点 ID，概括对象是这些原节点及各自完整后代 |
| `<!-- mm:item {"id":"s-child","expanded":false} -->` | 概括子树节点的身份和显示状态，不是正文内容 |
| 结构行末尾的 `^id`、元数据中的 `expanded` | 插件折叠/身份信息；不把它当作正文、不因此跳过后代，现有块引用仍有引用意义 |

一个原节点可被多个概括引用。比如 S1 的成员是 A/B，S2 是 B/C，S3 是 A/B/C：分别理解三条概括，S3 直接概括原 A/B/C，不因显示在更外侧或保存顺序靠后而理解为概括 S1/S2。

区分原分支记录与概括作者的总结：概括内容可能补充判断，但不会自动变成每个原成员都具有的属性，也不覆盖原文。回答时可表述为“某概括针对 A、B 归纳了……”。沿用知识库问答的来源引用与笔记内容/AI 推断区分。

## 节点间关系线

- 代码围栏外独立一行的 `<!-- mm:relations {"version":1,"links":[{"id":"r-1","from":"n-a","to":"n-b"}]} -->` 保存有向关系线；`id` 是线的身份，`from` 是起点节点 ID，`to` 是箭头指向的目标节点 ID。
- 主树节点的 ID 来自 `mm:node`，概括根和后代的 ID 来自 `mm:summary` / `mm:item`。按 ID 关联正文；关系线不是父子关系，不改变节点层级，也不能仅凭箭头推断因果、执行顺序或归纳含义，除非正文明确说明。
- 同一节点可以连接多个节点，双方同时完整复制时可能携带重映射后的关系线；不要按文字相同将不同 ID 合并。折叠隐藏连线不表示关联已删除。
- 理解方向和两端内容后，回答中省略关系线注释。未知版本、缺失端点、重复 ID 或损坏 JSON 保留原文并说明关联无法确认，不凭位置或同名节点补配。编辑节点正文时保留关系元数据与稳定 ID；删除端点前检查并同步处理受影响的 `links`。

## 虚拟分支与共享来源

- 代码围栏外独立一行的 `<!-- mm:grafts {"version":1,"links":[{"id":"g-1","source":"n-a","target":"n-b"}]} -->` 表示在 B 节点下显示 A 及其完整子树。`source` 指向唯一真实来源，`target` 是显示嫁接的位置，`id` 是引用本身的身份。
- 先按 `mm:node` / `mm:summary` / `mm:item` 的 ID 找到来源正文，再理解虚拟显示。B 的 Markdown 下没有第二份 A 正文；不要把虚拟显示计为新的独立知识，也不要据此改变 A 的真实父节点或推断新的因果关系。
- 来源的文字、样式和子树修改会同步到所有引用处，虚拟节点上的编辑也作用于来源。用户要求修改虚拟分支内容时修改来源正文；要求解除嫁接时仅删除相应 `links` 项，不删除来源子树。删除来源或目标前检查并处理受影响的引用。
- beta.34–38 的每处虚拟分支可保存独立的 `folds` 数组；每项的 `node` 是来源节点 ID，`path` 是外层引用内部经过的嵌套嫁接 ID，`expanded` 是该显示位置的展开状态。beta.39 起不再持久化此数组，但同一视图中的折叠仍与来源及其他副本独立。旧字段不代表正文或后代内容不同；普通正文编辑保留未知元数据，不自行批量清理历史标记，插件下次正常保存会去掉已识别的折叠字段。
- 缺失来源、重复 ID、未知版本或循环引用时保留原元数据，说明无法确定或展开关联，不按同名节点猜配，不递归展开循环。理解引用后在日常回答中省略内部注释。

## 显示标记与转义

- 回答中省略 `mm:*` 注释、内部 ID 和折叠状态；先完成关系解析，再省略。需要解释文件格式或定位关联时才展示这些标记。
- Markdown 转义如 `\#`、`\*`、`\[` 按字面字符理解；表格中的 `\|` 是单元格里的竖线，不能误作列分隔符。不要统一删除反斜杠，代码、路径、正则表达式中的反斜杠也属于内容。
- 元数据 JSON 中的转义按 JSON 解码；正文中的字面 `\n` 不自动变成换行。代码围栏和行内代码标记用于识别内容边界，保留代码本身的语义。

## 异常关联与编辑边界

- 引用缺失、ID 重复、概括区域损坏或版本未知时，指出无法确定的关联；保留可读正文，不凭位置、相似文字或邻近节点猜测成员，不静默删除异常区域。
- 只读理解不改写笔记。用户要求编辑时，配合 `note-editing`，保留 ID、区域边界、概括成员、折叠状态和现有链接；“回答中忽略标记”不等于从文件中删除标记。
- 修改节点文字不改其身份或关系；涉及删除、重排或增减概括成员时，同步检查受影响的 `members` 和共享引用，不能让概括留下悬空 ID。关联语义不能确定时保留原关系并说明。
- 无须为读取笔记加载插件源码、发布文档或 `mindmap-plugin-maintenance`；本 Skill 不授权发布、安装插件或修改客户端配置。
