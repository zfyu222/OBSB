# 第二大脑：分期实施计划

最后更新：2026-09-22

状态：第一期、第二期与第三期的手动完整整理版均已通过用户验收。当前正式整理入口为 OpenCode `workspace` 中的 `/run-nightly`；DSM 定时调度不属于当前交付。

## 1. 分期原则

- 总共三期，不继续拆成大量小版本。
- 每期交付一个可独立使用、可由用户实际测试的闭环。
- 每期先在测试内容上验证，再接入正式使用路径。
- 一期验收失败时停在本期修复，不带问题进入下一期。
- 不因进入后续阶段而破坏前一期已经稳定的同步或知识内容。
- 所有实际版本在首次部署当天核验，并记录到 `versions.lock`；不使用浮动版本。

## 2. 第一期：自托管同步与存储基础

状态：**已通过用户验收（2026-09-20）**。

### 目标

在没有 AI 的情况下，先得到一个稳定可用的 Obsidian 多设备知识库：Windows、Android、服务器三端能够通过自托管 CouchDB 与 LiveSync 实时同步 Markdown 和附件。

### 实施范围

1. 启动并验证群晖 Container Manager 与 Compose 能力。
2. 在非 DSM 共享目录 `/volume2/OBSB/` 下建立已确认的 `project/`、`runtime/`、`worktrees/`、`secrets/` 边界。
3. 建立外层框架 Git 与 `project/vault/` 内层知识库 Git；外层忽略整个 vault，内层只跟踪指定 Markdown。
4. 初始化空 vault：`InBox/`、`Raw/项目/`、`Raw/领域/`、`Raw/归档/`、`Drived/整理日志/`、`Assets/`。
5. 部署固定版本的 CouchDB 与 LiveSync CLI 容器，建立管理员账号、受限同步账号、E2EE V2 和同步数据库。
6. 配置 LiveSync 排除 `.obsidian/`、`.git/`、隐藏配置、缓存和临时文件；保持 Markdown 与 `Assets/` 同步。
7. 在 Lucky 配置 `https://obsync.hytzfy.dpdns.org:40087`，只暴露受认证的 CouchDB 同步入口。
8. 按“服务器 → Windows → Android”顺序初始化设备，并完成 `docs/Obsidian初始化配置.md` 中的客户端设置。
9. 记录精确版本、非秘密配置、启动/停止方式和故障检查命令。

### 用户验收

- Windows 新建 Inbox 笔记，服务器和 Android 能收到。
- Android 修改笔记，Windows 和服务器能收到。
- 粘贴图片后文件进入 `Assets/`，三端均可显示。
- 删除测试笔记后，三端结果一致。
- `.obsidian/` 与服务器 `.git/` 不会出现在其他设备。
- CouchDB 中的同步内容启用 E2EE；错误口令无法读取。
- 重启 LiveSync CLI、CouchDB 和 NAS 后，服务能够恢复同步。
- 制造一次并行编辑冲突，确认系统不会静默丢弃任一版本。

### 通过门槛

以上验收全部通过，并连续完成至少一次停止、重启、重新同步测试。通过前不部署 OpenCode 写入能力。

### 回退方式

停止 LiveSync CLI 与 CouchDB 容器，保留正式 vault、附件和容器数据目录；移除或禁用 Lucky 同步规则即可停止公网同步，不删除用户文件。

## 3. 第二期：交互式 AI 知识管理员

状态：**已通过用户验收（2026-09-21）**。第三期手动完整整理版也已于 2026-09-22 验收通过。

### 目标

用户可从电脑或手机浏览器进入 OpenCode Web，使用 DeepSeek 与知识库问答，并在当前会话中直接要求 AI 搜索、创建、修改、移动、合并或安全删除 Markdown；修改自动同步到 Obsidian。

### 实施范围

1. 构建固定版本的 `brain-agent` 容器，包含 OpenCode Web、Git、Skills 和确定性辅助程序。
2. 通过 Lucky 配置 `https://brain.hytzfy.dpdns.org:40087`，启用 HTTPS 与 OpenCode 登录认证。
3. 配置固定的 DeepSeek 默认模型，隐藏或禁用其他模型；API Key 只从秘密文件提供。
4. 引入并固定上游 `obsidian-markdown` Skill；实现项目自己的知识检索、问答引用、标签、递归摘要、Inbox 整理、通用编辑和笔记安全删除 Skills。
5. 实现标签扫描 CLI、Markdown/YAML/摘要校验 CLI 与 `vault-ops`；`vault-ops` 负责反向引用查询、移动、重命名、独立删除、合并收尾和引用维护。独立删除仍有反向引用时停止；只清理由被删笔记引用且全库已无其他 Markdown 引用的附件。
6. 用户主动编辑直接作用于正式 vault，视同用户编辑；不创建子会话或临时 worktree。OpenCode 展示操作过程，Git 工作区展示累计 diff。
7. 问答搜索文件名、正文、标签和所有摘要字段；回答就近引用 Obsidian 标题或已有块链接，并区分笔记内容、原文摘录、AI 推断与知识库未覆盖。
8. Agent 不访问 Inbox 中的外部 URL，不读取二进制附件，不读取 `secrets/` 与运行数据库。附件修改仅限用户明确删除笔记后由确定性 CLI 执行已确认的孤儿附件清理。

### 用户验收

- [x] 电脑和手机均能登录 OpenCode Web。
- [x] 提问后答案引用正确的 Obsidian 笔记位置，并正确区分原文与推断。
- [x] 要求 AI 新建或修改一篇笔记后，Windows 和 Android 能同步看到。
- [x] 要求 AI 将一篇 Inbox 内容合入现有章节，正文完整、源文件按规则移除、引用有效。
- [x] 标签最多 5 个且优先复用现有标签；递归摘要满足长度规则。
- [x] 移动或重命名笔记后，相关 wikilink 与嵌入仍有效。
- [x] 查询指定笔记时能列出反向引用；删除仍被引用的笔记会停止，删除无反向引用的笔记后只清理其唯一的无引用附件，共享附件保持不变。
- [x] 外部 URL 保持原样，任务记录证明没有抓取链接目标。
- [x] Git 为交互删除创建可恢复快照提交；当前未提交变化与按要求立即提交仍待最终联合检查。

2026-09-21 已完成的代表性测试：DeepSeek 只读问答、就近 Wikilink 引用与事实/推断/缺口区分；OpenCode 创建 Inbox 测试笔记并由 Windows、Android 同步确认；`vault-ops references` 精确返回引用来源与行号；重命名自动改写入站 Wikilink；存在入站引用时删除以退出码 2 拒绝；解除引用后删除测试笔记并分别建立恢复快照；Inbox 内容合并、标签复用、递归摘要、URL 字面保留及来源移除均通过；真实无引用测试图片被受限回收，仍被引用图片保持不变。用户已确认第二期验收通过，测试笔记已清理。

### 通过门槛

核心问答、直接编辑、同步、标签、摘要、合并和引用维护均通过代表性测试。通过前不启用凌晨无人值守修改。

### 回退方式

停止 `brain-agent` 并禁用 Lucky 的 OpenCode 规则；同步系统继续独立运行。若 AI 编辑需要撤销，使用内层 Git 工作区差异或已有历史恢复，不回滚整个同步系统。

## 4. 第三期：手动完整整理、恢复与运行加固

### 目标

由用户在 OpenCode `workspace` 中输入 `/run-nightly`，完整处理 Inbox 和自上次成功基准以来发生变化的 Raw 笔记；结果经过隔离、校验和冲突检查，用户可查看报告并在需要时恢复。

### 实施范围

1. 实现确定性完整整理编排程序、单实例锁和 `/run-nightly` 正式入口。
2. 任务开始前将服务器可见的未提交 Markdown 建立技术快照，并维护上次成功整理基准。
3. 为无人值守任务创建临时 Git worktree 和一个命名 OpenCode Session，由总 Skill 调用所需子 Skill。
4. 实现权威外部校验与最多两轮自动修正；失败结果不应用到正式 vault。
5. 应用前检查运行期间到达的正式 vault 变化；不相交变化保留，冲突时保留正式内容并报告失败。
6. 成功应用后建立独立 Git 提交并推进适当基准；有变化或失败时生成带运行时间的 `Drived/整理日志/YYYY-MM-DD-HHMMSS.md`。
7. 成功且无变化时不生成报告、不创建提交；失败时生成报告且不遗漏失败项。
8. 实现按任务撤销和按笔记恢复，通过新的恢复提交保留历史。
9. 完成幂等性测试、容器重启/中断恢复和故障诊断说明（见 [夜间整理故障诊断](夜间整理故障诊断.md)）；不在当前范围增加日志脱敏或磁盘空间检查。

### 用户验收

- 通过 OpenCode `/run-nightly` 手动触发完整任务，Inbox 被正确分类、移动或合并；同一天多次有变化或失败的运行保留各自带时间的报告。
- 白天直接编辑过的 Raw 笔记，其标签和递归摘要在夜间得到维护。
- 整理日志按笔记逐条给出简洁自然的中文处理说明，并链接相关笔记；不展示内部动作标签或重复说明移动后的来源移除。
- 无变化成功任务不产生报告和 Git 提交。
- 人为制造格式校验失败，确认最多修正两轮，仍失败时不污染正式 vault。
- 人为制造任务期间同文件冲突，确认正式内容不被覆盖。
- 任务运行期间重启或中断后，不错误推进成功基准。
- [x] 可以撤销一次 AI 整理提交或恢复指定笔记，同时保留后续历史。
- 次日从 Obsidian 报告、OpenCode 会话和 Git 三个入口均能检查结果。

### 正式验收结果（2026-09-22）

- 已完成有变化成功、无变化成功和并发冲突失败三类真实运行；冲突时正式 vault 未被覆盖。
- 已验证每次有变化或失败的运行只由编排器生成一份带运行时间的中文报告；无变化成功保持静默。
- 已覆盖单实例、幂等性、锁恢复和中断恢复的自动化测试；恢复能力已完成演练。

### 通过门槛

连续完成至少三次代表性运行：有变化成功、无变化成功、包含失败或冲突；三类结果均符合规则后，第三期手动完整整理版通过验收。该门槛已于 2026-09-22 达成。

### 回退方式

不再执行 `/run-nightly` 即可停止完整整理，不影响 OpenCode 交互和 LiveSync。未通过校验的 worktree 直接丢弃；已应用结果通过新的 Git 恢复提交撤销，不重置整个仓库。

## 5. 阶段之间的控制点

每一期结束时提供：

- 已完成范围和实际版本；
- 用户可执行的验收步骤；
- 已知限制与未通过项目；
- 当前运行状态、停止方式和回退方式；
- 对共识文档、初始化清单和版本锁定文件的更新。

只有用户明确回复本期验收通过，才开始下一期。修复本期缺陷不视为新增一期。
