# 思维导图概括功能设计

状态：2026-10-12 已完成实现及本机验证，发布版本 `0.2.6-beta.12`。基于用户截图、五项澄清及后续补充；用户已要求直接实现至开发完成，并持续授权检查通过后自动发布 beta。以下为本次实现规则。

## 用户已明确的规则

1. 选择集合先过滤已有选中祖先的后代：同时选中父节点和其子孙，只保留父节点。过滤后的成员必须有同一个直接父节点，并且全部位于主图 root 的同一侧（全部左侧或全部右侧）。root 本身没有同侧兄弟关系，不作为概括成员。
2. 连续性按共同父节点的 `children` 顺序判断，不按屏幕距离判断：排序后索引必须无缺口。夹在成员中间的兄弟即使隐藏、很小或离得远，也不能忽略。首次创建不自动纳入未选中的兄弟。
3. 支持一个或多个成员。单节点概括与多节点概括采用相同关系模型，无须特殊保存格式。
4. 概括符号包围每个成员及其全部当前可见后代的联合包围盒。折叠成员后只计算仍可见的节点，不计算隐藏后代；这只改变显示尺寸，不改变概括成员或关联的完整子树语义。
5. 共同父节点折叠后，括号和概括整棵子树隐藏；重新展开恢复。任何祖先折叠导致成员不可见时也适用。不因隐藏删除 Markdown、关系或 ID。
6. 概括本身是一棵独立子树，可以继续添加、编辑、删除和折叠自己的子节点。它不成为原节点的新父节点，也不挂入原主树的 `children`。
7. 概括子树集中存放于原 Markdown 文件末尾的专用区域；原主树正文与概括子树区分开解析。
8. 概括通过成员 ID 关联原节点；创建时自动给需要关联的原节点写稳定 ID 标记。一个原节点可以被多个概括引用，最后一个概括引用解除后才移除为此功能添加的 ID 标记。
9. 原成员全部被删除时，该概括关系及整棵概括子树一起删除；与原成员删除放进同一历史事务，撤销完整恢复。
10. 用户补充截图中的最右侧概括直接关联最初三个原节点，不关联左侧两个概括节点。多个概括之间没有因视觉位置产生的依赖关系。

“公共父类折叠时，概括也小时”按“公共父节点折叠时，概括也消失”理解。

## 操作与选择

顶部工具栏提供“概括”图标及悬停说明，命令面板提供同名入口。有至少一个有效成员才允许创建，校验失败明确提示不同父节点、跨 root 左右两侧或兄弟不连续。

创建括号及概括根节点，默认文字“概括”，立即进入文字编辑。概括子树内复用普通节点文字编辑、Tab 添加子节点、Enter 添加同级节点、折叠、选中和批量操作；概括根没有普通同级节点，Enter 不凭空创建新的关联关系。

点击括号选中概括根。非文字编辑状态下删除概括根，删除该关系及整棵概括子树，保留原分支；删除概括子节点只影响概括子树。编辑状态沿用 beta.11 的原生文字拖选、复制粘贴和统一历史。原节点与概括节点的选择类型须明确，混合选择不能误交给仅处理主树的旧命令。

## Markdown 保存格式

使用隐藏 HTML 注释界定文件末尾专用区域，在其中保存普通 Markdown 子树；概要不用 callout。beta.12 起识别此格式；更早版本不能正确显示概要关系。

```md
# 预测修正

- 单位式回滚 <!-- mm:node {"id":"n-a"} -->
  - 直接回滚
- 回滚重放 <!-- mm:node {"id":"n-b"} -->
  - 固定帧模拟
  - 非固定帧重放

<!-- mm:summaries:start {"version":1} -->
## 概括子树区

### 两种回滚方案的共同点 <!-- mm:summary {"id":"s-1","members":["n-a","n-b"]} -->
- 都用于修正预测结果
  - 恢复旧状态
  - 重新执行逻辑
- 需要保持状态一致性

### 单位式回滚的注意事项 <!-- mm:summary {"id":"s-2","members":["n-a"]} -->
- 技能状态也需要恢复

<!-- mm:summaries:end -->
```

`mm:summary.id` 是概括根身份，`members` 只记录原分支根 ID，不逐个记录后代；标题与后面的 Markdown 是这棵概括子树的内容。多个概括可以共享成员 ID，例如上例 `n-a` 的引用数为 2。位置、括号曲线和尺寸都由布局计算，不写入 Markdown。

开始/结束标记才是区域边界，不能只凭“概括子树区”标题截取笔记。先提取并解析该区域，再把剩余主树送入原 Transformer，避免该区域成为主图新增分支。普通 Markdown 阅读与 AI 编辑能同时看到原文、独立总结和引用关系。无概括时建议移除空专用区域。

主树成员在结构行上保存 `mm:node` ID；代码和表格内容放在其后的正文，避免注释破坏代码围栏或表格。概括子节点使用 `mm:item` 隐藏注释保存 ID 与 `expanded` 状态，根元数据也保存 `expanded`。多段正文、代码、表格和图片嵌入已做往返验证。

现有 `^id` 被插件兼作折叠标记；新增 `mm:node` 稳定关联 ID 必须与折叠状态分开读取，增加 ID 不能触发折叠。清理无用关联标记时不删除原本的 Obsidian 块 ID 或仍用于折叠的标记。

手工编辑导致 ID 重复、引用缺失、区域损坏、未知版本或成员不再合法时，保留原始片段和概括正文，提示修复，不能猜测成员或静默删除。无损保存须同时保护主树及未解析概括区域。

## 关系模型与 ID 生命周期

运行时模型建议：`MindMapDocument = { mainRoot, summaries }`；每条 `Summary` 为 `{ id, memberIds, root, version }`，其中 `root` 是具有完整 `children` 的独立节点树。共同父节点和 root 左右侧从原成员推导；概括根所在方向由关联组决定。

建立成员到概括关系的反向索引或引用计数。创建概括时复用已有稳定 ID，仅给尚无稳定 ID 的成员分配并写入标记。引用计数不必写入 Markdown，重开时由全部关系重建。

删除概括或解除某个成员引用时，检查该 ID 是否仍被其他概括使用；引用为 0 后删除该功能管理的 `mm:node` 标记。其他概括继续使用同一 ID，不重编号。未解析但仍保留的关系若可能引用该 ID，暂缓清理，防止破坏可恢复关系。运行时节点对象可以继续保持内部 ID，清理的是不再需要持久保存的关联标记。

创建、删除、修改引用、补齐/清理 ID 标记与概括子树操作组成原子命令，共享当前图的统一撤销/重做历史。撤销删除时恢复整棵概括子树、关系和原 ID，不能依靠下次渲染补救。

## 自动布局

每条概括按成员及可见后代的联合包围盒确定括号上下范围与外缘。概括根接在括号中点，其子树向外继续展开；左向分支镜像显示。单节点没有可见后代时，括号包围该节点的可见尺寸。

占位测量必须包括概括的整棵可见子树，而非只算概括根文字。先排布主树，再从主树外缘向外分配概要通道，以整棵概要子树的宽高避让；图片及 Markdown 异步渲染后重算尺寸。导出、居中、缩放和框选的可见元素集合也包括概括子树。

同一成员允许被多个概括引用，因此多个合法连续范围可能相同、包含或重叠；不能沿用旧草案“一节点只属于一个概括”的限制。建议对重叠范围分配不同外侧通道，分别绘制括号与概括子树，再根据整棵子树尺寸避让。通道位置是运行时布局结果，不写入 Markdown，本机浏览器已检查左右两侧及重叠范围避让。

用户补充截图对应的关系示例：原兄弟节点 A、B、C，分别创建 S1 → [A, B]、S2 → [B, C]、S3 → [A, B, C]。B 同时属于三个概括。S3 即使显示在 S1/S2 更外侧，也直接引用 A/B/C；其括号范围仍由原节点可见子树计算，不由 S1/S2 的尺寸计算。绘制时综合所有括号、概要根和各自子树分配空间，避免通道穿过其他概要内容；通道顺序优先较小范围、较大范围向外，并以稳定关系顺序处理同范围多个概要。

删除 S1 不改变 S2/S3，也不删除仍由它们引用的成员 ID。删除原节点 A/B 后，S1 全部成员消失，因此删除 S1 整棵概括子树；S2 和 S3 都还引用 C，继续保留，括号收缩为 C 的可见子树范围。继续删除 C 时，一起删除 S2/S3 子树。每次原节点删除与全部受影响关系、子树、ID 标记清理均为一个事务。

主 root 的左右自动分配需尊重已有概括关系。含共享成员的概括范围组成一个连通布局组，作为整体分配到一侧，避免节点数量变化把同一个有效概括拆成跨左右两侧。用户显式改变布局时重算整组位置。

## 联动规则

按实现前讨论采用以下默认规则：

| 操作 | 行为 |
| --- | --- |
| 在概括范围内部添加或移入同级节点 | 自动加入受影响的所有概括范围，同一命令补 ID 与引用；边界外不自动加入 |
| 删除或移出部分原成员 | 解除受影响概括的相应引用，清理引用归零的 ID；只剩一个成员仍有效 |
| 同一父节点下重排 | 移动部分成员解除其引用；整组移动保留关系；范围内部的新节点纳入所有覆盖该位置的概括 |
| 复制完整原分支组 | 携带全部成员均在复制范围内的概括子树，分配新关系/节点 ID 并重映射引用；部分复制不带悬空关系 |
| 单独复制概括子树 | 复制为普通子树内容，不携带指向源文档成员的关联 |
| 在概括子树上再次点击概括 | 当前截图没有递归概括需求，最外侧概括仍直接关联原节点；概括自身子节点的再次概括不纳入当前设计范围 |

## 实施顺序与验收

1. 保存层：末尾独立区域、完整子树解析与序列化、稳定 ID、引用计数清理、未知/异常片段保留。
2. 文档模型和事务：主树与概括树分别遍历；创建/删除/编辑、成员联动、撤销与剪贴板重映射。
3. UI 和布局：工具栏、单/多成员校验、子树编辑、左右括号、多概括通道、折叠隐藏及导出。

验收覆盖单节点、同父连续兄弟、父子去重、非连续或跨 root 左右侧拒绝；完整可见子树包围盒、折叠成员及共同父节点；概括子树 Tab/Enter/编辑/折叠；一节点多概括与最后引用删除 ID；创建保存重开、末尾区域隔离、代码/表格/图片保真；长子树和多个概括防碰撞；删除与一次撤销完整恢复；跨图复制引用重映射、异常手改保留原文；实际 bundle 与浏览器交互，最后进行 Obsidian 实机验收。

主要入口为 `MindMapView.setViewData/mdToData`、`MindMap.getMarkdown`、`INode`、`Layout`、`Cmds/Execute/History` 和 `clipboard.ts`。新增独立 `summary/model.ts`、`summary/markdown.ts` 和 `summary/manager.ts`，概括节点复用原节点渲染和编辑能力。

- 真实浏览器事件配合模拟节点，验证单节点与 A/B、B/C、A/B/C 重叠概括、可编辑独立子树、左右布局避让、保存重开、成员折叠后尺寸收缩、共同父节点折叠后隐藏、完整组复制的 ID 重映射、原成员全部删除及一次撤销恢复、删除最后概括后清理 ID。
