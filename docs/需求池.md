# 第二大脑需求池

最后更新：2026-09-17

本文件保存后期想法，不属于当前阶段的实现范围，也不作为当前需求对齐的阻塞项。只有用户明确决定重新纳入时，才更新 [需求与方案共识](需求与方案共识.md) 并细化方案。

## P01：Drived 综合推导文档

- 状态：后期想法，暂缓讨论与实现。
- 来源：用户最初希望在 `Drived/` 保存 AI 基于 Raw 思考、综合形成的新文档；2026-09-17 明确尚未想清楚，移入需求池。
- 设想：AI 关联一篇或多篇 Raw 笔记，形成新的思考或综合结论。
- 保留的原始约定：目录沿用 `Drived` 拼写；未来若启用，文档应引用 Raw 来源。
- 尚未确定：用户主动触发还是 AI 自动生成、生成时机、内容标准、展示和维护方式。
- 当前边界：不纳入夜间记忆整理，不默认生成综合推导文档或主题建议，也不为此要求开发插件或其他组件。当前方案会使用 `Drived/整理日志/` 保存运行报告；该用途不属于本需求项。

## P02：RAG 语义搜索

- 状态：后期需求，第一期不实现。
- 来源：原始需求提出可用 RAG 做语义搜索；2026-09-17 用户明确移入需求池。
- 设想：通过向量或混合检索召回语义相关但没有共享关键词的笔记，为搜索和知识库问答提供候选内容。
- 当前替代方案：OpenCode 使用内置 `glob`、`grep`、`read` 和 `bash` 等工具，按文件名、关键词、标签和各级摘要搜索，再读取候选正文。
- 重新评估条件：实际使用中频繁出现“知道内容存在但关键词和摘要无法召回”、知识库规模明显增长，或问答准确率受召回限制。
- 未来约束：RAG 索引只能是可从 Markdown 重建的派生缓存，不能替代 Markdown 事实源。
- 尚未确定：切块方式、Embedding 模型、索引存储、增量更新、中文检索效果及成本。

## P03：AI 隐私保护与敏感笔记隔离

- 状态：后期需求，第一期不实现。
- 来源：确定使用 DeepSeek 云端模型后，讨论过为 AI 设置禁读范围；2026-09-17 用户决定第一期先不设置，但要求将隐私保护记录到需求池。
- 设想：通过专用目录、标签或规则标记敏感笔记，禁止 Agent 读取、禁止发送给云端模型，或在发送前进行确定性脱敏。
- 当前方案：第一期 Agent 可以读取整个 vault，并按任务需要将相关内容发送给 DeepSeek。
- 未来约束：限制必须由程序层强制执行，不能只依赖提示词；搜索、问答、夜间整理和用户主动编辑任务应遵守同一边界；日志、Git diff 和错误信息也不得泄露被保护内容。
- 尚未确定：采用路径还是标签划分、是否支持字段级脱敏、密钥及个人信息检测、用户临时授权方式，以及被引用笔记跨越保护边界时如何处理。
