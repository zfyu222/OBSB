# Obsidian 任务管理插件需求

状态：开发基线 v0.6（0.2.1 完成时间选择器，待实机验收）

更新日期：2026-10-27

来源：2026-10-23 至 2026-10-27 的用户需求讨论。

用户于 2026-10-26 接受全局任务归档及领域休眠方案，并授权开始开发，随后要求提交 Git 以便 BRAT 更新。此前仅设计的限制已被后续授权取代；首版已发布至独立仓库 `zfyu222/obsb-tasks` 的 `0.1.0` Release，不自动安装正式 vault。用户原始需求、助手建议与首版选定默认值分别记录。

实现及测试边界见[插件说明](../plugins/obsb-tasks/README.md)。

## 1. 产品目标

在当前 Obsidian 知识库内管理任务：通过思维导图组织领域和任务，通过列表查看所有任务，支持长期积累、归档和按时间回顾。任务与普通知识文档分区存放，但可相互引用。

### 2.1 节点示例

```text
root                            [结构根]
├─ 更新开发环境                 [任务，不属于领域]
├─ AAA项目                      [领域]
│  └─ 完成注册系统开发          [任务]
│     ├─ 完成注册系统需求确认   [任务]
│     ├─ 完成注册系统前端开发   [任务]
│     └─ 完成注册系统后端开发   [任务]
└─ 游戏技能系统                 [领域]
   ├─ 实现技能冷却              [任务]
   └─ 修复技能同步问题          [任务]
```

“AAA项目”“游戏技能系统”只分类，不因下属任务全部完成而自动变成已完成任务。

### 2.2 当前文件与归档的边界

- 当前任务文件承载从 root 出发的任务树，包含未完成和已完成任务；归档数据在当前文件之外保存。
- 标记完成不移动任务、不自动隐藏，也不从正常搜索中排除。用户主动选择状态筛选与默认流程是两回事。
- 归档后，当前文件不再保留该任务的完整节点或注释；默认流程不得通过扫描归档或历史把它重新带回。
- 当前任务统计也默认只依据当前文件，不自动将已归档任务计入；历史成果通过显式回顾查询查看。该统计口径是对“默认流程等于没有这个任务”的落实。
- 归档不是丢失记录：保留用户要求的归档查询与时间段导图入口。归档文件格式、批次组织和关系保留方式待技术设计。

## 3. 待确认的产品规则

以下均为助手建议或需求中尚未明确的语义，不作为实现时的默认授权。

| 编号 | 问题 | 建议起点 |
| --- | --- | --- |
| Q01 | 领域是否可以嵌套领域？ | 允许，例如“工作 → AAA项目 → 游戏技能系统”。 |
| Q02 | 一个任务能否属于多个父节点？ | 先采用单父节点树、禁止循环；跨领域关联通过标签或链接表达。 |
| Q03（已确认） | 未选领域的任务放在哪里？ | 直接挂在共同 root 下，不强制创建“未分类”领域，见 R14。 |
| Q04 | 父子任务如何完成、重开？ | 子项全完成时提示完成父项；有未完成后代时不静默批量完成。重开时保留历史完成记录。 |
| Q05（已确认） | 完成与归档是什么关系？ | 完成留在当前文件，显示与检索正常；归档从当前文件移出并退出默认流程，见 R07、R08、R15。 |
| Q06 | 如何归档部分完成的任务树？ | 可单独归档已完成子项并保留父子关系；父项有未完成后代时不能整树作为已完成归档。 |
| Q07 | 是否支持恢复归档？ | 建议支持，保留身份、关联和完成记录；原父节点不可用时选择恢复位置。 |
| Q08（领域部分已确认） | 是否需要领域归档和取消任务？ | 领域采用手动休眠和恢复，不随任务完成归档；首版取消任务不自动归档。 |
| Q09（语义已确认） | “默认不搜索”覆盖哪些入口？ | 默认流程视归档任务不存在；插件、原生搜索与日常 AI 检索如何落实该边界，属于集成设计问题。显式归档／历史查询可以访问。 |
| Q10 | “时间段”依据什么筛选？ | 可选完成、创建、期间活动；具体默认口径待确认。 |
| Q11 | 是否需要还原某天当时的图？ | 区别于按日期筛选。如需要，须记录标题、属性和父子关系变更，不能只依赖半年一次的归档快照。 |
| Q12 | 历史图采用当时关系还是现在关系？ | 历史回放采用当时关系；期间筛选图另定口径，并显示必要祖先作为上下文。 |
| Q13 | 首版支持哪些设备？ | 建议 Windows 与 Android，离线可用并复用现有同步；支持范围待确认。 |
| Q14 | 注释是单份备注还是带时间的评论串？ | 建议先采用单份可编辑 Markdown 正文；不引入多人评论。 |
| Q15 | 任务正文能否在原生编辑器或 AI 中修改？ | 建议允许，定义元数据校验、错误提示和增量刷新规则；不自动吞掉未知字段。 |

### 3.1 候选任务属性

用户明确提出属性类别，尚未确认下表中的具体规则。

| 属性 | 建议规则 |
| --- | --- |
| 名称 | 创建时必填，描述具体结果。 |
| 状态 | 待办、进行中、等待中、已完成、已取消。 |
| 重要程度 | 高、中、低，默认中；取值是否扩展待确认。 |
| deadline | 可空，支持日期及可选时间；日期截止的时区语义需明确。 |
| 计划执行日期 | 与必须完成的 deadline 分开。 |
| 完成时间 | 完成时自动记录，可通过本地日期时间选择器修正，内部保存 ISO 时间；重开时清空。 |
| 预计／实际工作量 | 统一数值单位，界面可用小时输入；首版是否包含实际工作量待确认。 |
| 创建／更新时间 | 自动维护，不与归档时间混用。 |
| 标签 | 提供跨领域筛选。 |
| 注释 | 完整 Markdown 正文，支持关联知识文档。 |
| 归档时间／批次 | 支持按完成时间和归档时间分别查询。 |

逾期建议由 deadline 和状态推导。父任务预计工作量与子任务汇总应区分，避免重复累计；进度是否按叶子任务或工作量加权待确认。默认统计只处理当前文件中的任务；归档成果在历史查询中展示，不自动混入当前进度。

## 4. 视图与交互建议

### 4.1 思维导图

- 区分领域与任务外观；任务显示状态、重要程度和 deadline。
- 从共同 root 展示领域及直接挂载的任务；已完成未归档任务默认仍在图中。
- 支持新建、重命名、拆解子任务、折叠展开、定位和调整层级；每次调整校验节点类型和循环。
- 节点显示注释入口，完整内容在详情面板按需编辑、预览，不同时渲染全图注释。
- 支持领域聚焦、搜索定位；拖动、键盘快捷键、撤销重做和子树复制的首版范围待确认。
- 若复制任务子树，应生成新身份，明确是否重置完成及归档记录，不能误成同一任务的第二份事实。

### 4.2 列表

- 任务与子任务各占一行，领域不作为任务行；用所属路径保留上下文。
- 候选列：名称、所属路径、状态、重要程度、deadline、计划日期、预计工作量。
- 支持属性筛选、排序、详情编辑及定位到导图；具体快捷入口待确认。
- 默认包含当前文件中的已完成任务，排除归档；两种视图编辑同一任务时结果一致，不分别保存两份内容。

### 4.3 注释与链接

- 建议支持原生 Markdown 的标题、列表、表格、代码块、双链、标题／块引用、Callout 和嵌入。
- 相对链接按节点来源文件解析；普通文档可反向引用节点。
- 改名、归档、恢复时保持引用可达；链接维护机制待技术设计。
- 其他社区插件扩展语法及自定义详情编辑器中的 Live Preview 兼容性不预先承诺。
- 引用附件仍遵守当前附件规则：二进制附件在 `Assets/`，本轮不读取或修改附件。

## 5. 存储与知识库集成边界

已明确：数据位于 Raw 下的独立目录，注释采用 Obsidian Markdown，能够与普通文档互引。当前任务树保存在当前任务文件中，已完成节点仍在其中，归档节点必须移出该文件。

此前助手建议的“一个节点一篇 Markdown”不再作为本需求的存储候选。改为以包含多个节点的任务导图文件为设计基础；文件内部节点属性、Markdown 注释和稳定引用的编码方式待技术设计。是否支持多个任务图文件、归档按批次还是时间分文件、具体文件名和历史格式尚未确认。`Raw/任务管理/` 仍是建议目录名。

集成设计必须说明：

1. 哪些是需同步和备份的正式数据，哪些是可重建的本地缓存；历史若用于回放，也属于正式数据。
2. 如何兼容当前 LiveSync 和知识库 Git 范围；不增加与既有同步竞争的另一套事实源。
3. 如何识别任务文档，避免完整整理将其作为普通笔记随意合并或重构；任何 Skill、校验或整理规则调整另行实施。
4. 归档、历史与当前任务的检索边界如何分别生效；普通文档中的归档节点引用不能导致默认搜索或统计递归纳入归档数据。
5. 如何遵守现有结构操作经 `tools/vault_ops.py` 的约束，并兼容移动端；必要适配另出方案，不绕过规则直接移动删除。
6. 多设备或外部编辑冲突如何检测、保留和恢复；不能只靠最后一次写入静默覆盖。

本轮不修改正式 vault、`.obsidian` 或同步配置。插件启用时不写数据，用户首次打开面板才创建当前文件。框架 `knowledge-qa` 已加入归档／休眠／事务的默认检索排除；`note-editing` 补充任务格式保护。生成的任务文档以 `nightly_maintenance: skip` 复用现有完整整理排除机制。

## 6. 性能需求与技术候选

性能是产品约束，Rust 是用户提出的技术选项，并非已选语言。

### 6.1 建议的性能约束

- 列表使用虚拟滚动，不随任务总数创建全部行。
- 导图支持分支折叠、按需展开和视口裁剪；大范围概览采用简化显示，不要求同时绘制所有详细节点。
- 注释按需读取、渲染；关闭面板释放相关资源。
- 启动先恢复可重建索引，后台增量校验；首次建索引应可观察进度，不长期阻塞交互。
- 属性查询与注释全文检索分开处理；单个节点修改不触发全库重新解析。
- 更新受影响节点及祖先统计，避免每次编辑重算整张图。
- 归档与历史按需查询，长历史采用分片或检查点等策略。
- 缓存删除后可由正式数据重建，缓存不成为唯一事实源。

### 6.2 技术候选，均未定案

| 候选 | 适用点与验证事项 |
| --- | --- |
| TypeScript | Obsidian 集成、交互和文件操作；作为首版候选，需实测规模与设备表现。 |
| Web Worker | 布局、索引和历史计算等可移出主线程的任务；验证兼容性和数据传递成本。 |
| Rust / WebAssembly | 仅对实测 CPU 瓶颈评估；计入调用、转换、包体与内存开销。 |
| 本机 Rust 程序 | 安装和移动端适配成本较高，暂不建议作为首版前提。 |

不得仅凭语言宣称性能达标。重点测量大型任务文件的解析、序列化、保存与同步成本，以及同一文件跨设备编辑冲突；不能只测索引查询和节点绘制。

### 6.3 建议的性能测试矩阵

测试 1,000、10,000、50,000 节点，覆盖深树、宽树、长注释、大量链接、归档和历史。这些是建议测试档位，不是已确认容量承诺。

记录冷／热启动、首屏可操作、搜索筛选、展开拖动、编辑保存、批量归档、历史查询耗时及内存；同步成本与桌面、Android 实机分别测试。开发前确定测试设备、数据样本、可见节点数量和各项 p95 响应指标；目前不写未经验证的毫秒承诺。

## 7. 候选验收场景

已明确需求对应的验收场景：

| 场景 | 预期 |
| --- | --- |
| 创建领域、任务和多级子任务 | 结构与业务类型一致；任务下不能创建或拖入领域。 |
| root 下直接创建任务 | 无需选择或创建领域，能继续添加子任务。 |
| 切换导图与列表 | 同一任务的名称、属性及注释一致；列表平铺任务。 |
| 编辑节点注释 | 可保存并预览约定范围的 Obsidian Markdown。 |
| 节点与普通文档相互引用 | 双向链接可访问正确对象，不把普通文档搬入任务目录。 |
| 完成任务但不归档 | 节点和注释仍在当前文件，默认导图、列表和正常检索均能找到。 |
| 手动归档已完成任务 | 节点和注释已从当前文件移出；默认显示、检索、统计和处理不包含它，显式归档入口仍可查到。 |
| 选择时间范围查看任务图 | 按最终确认的日期口径返回任务和必要上下文。 |
| 大量任务操作 | 按最终确定的数据规模、设备与响应指标验收。 |

待产品规则确认后补充：部分子任务归档后的关系与进度、恢复归档、任务重开、历史时点还原、跨设备冲突与外部编辑。

若要求历史状态回放，应明确可保证的起点和完整性：从记录机制启用后开始；尚未同步的编辑以及未被观测到的外部中间状态不能伪装为完整历史。

## 8. 范围与下一步

用户已授权首版开发。为避免反复确认，以下作为本次实现的工程默认值，不追认为用户原始需求：允许领域嵌套；单父树；完成父项前需处理未完成后代，不自动联动完成；休眠整个领域及其已完成后代；恢复以批次为单位并补齐必要祖先；日期按本机时区的创建／完成日筛选；deadline 首版只支持日期；支持 Windows／Android 的跨平台接口，实机表现待验收。

首版已实现：共同 root、节点编辑及父节点调整、导图和虚拟列表、任务属性、Markdown 注释预览、全局完成任务归档、空领域检查、领域休眠和恢复、归档批次恢复、稳定节点 URI、按日期范围的任务图、冲突拒绝和归档中断恢复。采用 TypeScript，无其他导图插件依赖。

0.1.1 根据用户反馈增加：Tab 新建子任务、Enter 新建同类型同级节点，默认属性并直接编辑名称；右侧属性栏自动保存所有属性、注释及节点类型，输入框／IME／归档视图不触发建节点快捷键。非法类型转换不静默调整后代，保存失败保留草稿；关闭失败可从本机恢复副本找回。

0.2.0 选定实施方式：从用户 fork 的 beta.41 提取实际 Layout、selection、History，实现不依赖原插件安装的任务适配层；不是另写一套仿导图算法，也不整体复制概括、嫁接及导入功能。复用代码固定来源版本，保留 MIT 声明，原 fork 不作改动。

画布加入双侧／右侧布局、曲线连线、标题尺寸与分支间距、右键平移、抓手模式、滚轮／触控板平移、锚点缩放、触摸手势、框选、多选、节点子树拖放、方向键导航和运行期撤销／重做。拖放和撤销经任务类型与版本冲突校验后才写入；归档、休眠、恢复不进入此栈。继续保留虚拟节点渲染和既有 Markdown 数据格式。
